Что означают FPS, Bitrate, RTT, Jitter, Loss и Route?

FPS — сколько кадров видео приходит за секунду. 30 FPS — плавно; 15 FPS уже заметно дёргается.

Bitrate — скорость самого видеопотока в Mbps. Чем выше, тем больше деталей и расход трафика.

RTT — сетевой round-trip time текущего WebRTC-участка. Для SOURCE это браузер↔телефон; для RELAY — браузер↔source-браузер. Это не полная задержка «камера→экран».

Jitter — насколько нестабильно по времени приходят пакеты. Высокий jitter даёт рывки даже при хорошем среднем ping.

Loss — процент потерянных пакетов. Для видео желательно около 0%; несколько процентов уже могут портить плавность.

Route — ICE-маршрут текущего участка: host — локальный адрес, srflx — прямой маршрут через NAT/STUN, relay — через TURN. У RELAY-зрителя поток идёт через source-браузер.

RTT — это сетевой round-trip time, а не точная «камера→экран» задержка. Для glass-to-glass задержки нужен отдельный тест таймером.
